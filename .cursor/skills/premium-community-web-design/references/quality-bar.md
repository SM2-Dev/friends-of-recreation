# Quality bar

## Before implementation

- Audit the real repository and identify reusable primitives.
- Identify approved versus missing brand assets.
- State the page's content hierarchy and dominant visual idea.
- Decide how the design will remain recognizable without the logo.
- Define mobile content order before desktop details become fixed.

## During implementation

- Work from page-level composition before abstraction.
- Use semantic tokens and established components where appropriate.
- Keep client JavaScript and decorative effects proportionate to their value.
- Use real content shapes and test long titles, missing images, empty lists, and validation errors.
- Preserve accessible names, landmarks, focus states, contrast, reading order, and reduced-motion behavior.

## Visual review

Review at small mobile, large mobile, tablet, desktop, and large desktop sizes. Check:

- mission and CTA clarity
- heading wraps and text measure
- image crop and subject visibility
- section rhythm and transitions
- alignment relationships
- control size and focus state
- forms in default, pending, error, and success states
- events with and without an end date
- external-link clarity
- long project amounts, names, and descriptions
- no-content and missing-image behavior

## Anti-template review

Remove or redesign work that relies on:

- card grids as the page structure
- equal visual weight for unlike content
- repeated eyebrow, heading, copy, CTA stacks
- decorative pills and icon tiles
- default framework typography and radii
- generic gradients, glows, glass, grids, or blobs
- repeated centered alignment
- stock photography or decorative sports icons
- animation without a communication purpose

## Final test

The result should be clear, memorable, specific to local recreation, maintainable in Payload, and usable without motion or a mouse. It should feel confident enough for donors and partners while remaining welcoming to families and volunteers.
